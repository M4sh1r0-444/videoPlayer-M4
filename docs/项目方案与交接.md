## 一、项目整体介绍

### 1.1 定位与目标场景

本地视频学习播放器：把散落在硬盘里的网课视频按 **科目 → 课程 → 分集** 自动组织，配续播、倍速、进度标记和讲义/习题关联，服务考研/自学等长周期学习场景。

设计原则：
- **不要求用户整理文件**：不改名、不搬家，目录约定自动识别 + 手动导入兜底；
- **数据全本地**：进度/配置存单个 JSON，无任何联网功能；
- **界面中文**，键盘优先（学习场景高频操作）。

### 1.5 数据模型（learn.json）

```jsonc
{
  "roots": ["D:\\网课\\数学"],                     // 自动扫描的根目录
  "customCourses": [{                            // 手动导入的课程
    "id": "cxxxx", "subject": "数学", "name": "张宇高数",
    "sourceDir": "D:\\下载\\张宇", "videos": ["<绝对路径>"],
    "docs": [{ "path": "<绝对路径>" }]
  }],
  "docsByCourse": { "<扫描课程目录>": ["<doc路径>"] },  // 挂到已扫描课程的讲义
  "docsIgnored": { "<扫描课程目录>": ["<doc路径>"] },   // 二阶段：被用户移除的扫描讲义（重启不复活）
  "docBinds": { "<doc路径>": 1 },                 // 二阶段：讲义手动关联的分集下标（优先于自动匹配）
  "videos": {                                    // 每视频进度（键=绝对路径）
    "<视频绝对路径>": {
      "position": 1680.5, "duration": 3820.0,
      "completed": true, "lastPlayedAt": "ISO时间"
    }
  },
  "stats": { "daily": { "2026-09-18": 3700 } },   // 二阶段：每日累计播放秒数（本地日历天）
  "ai": {                                          // M7：AI 侧边栏配置（本地明文存储，文档明示）
    "baseUrl": "https://api.deepseek.com/v1",      // OpenAI 兼容根地址（含 /v1，不含 /chat/completions）
    "apiKey": "sk-...",                            // 仅存本机 learn.json；密码框遮显；绝不写日志
    "model": "deepseek-chat",
    "contextEnabled": true,                        // 自动附带当前科目/课程/分集/播放位置
    "systemPrompt": ""                             // 用户自定义系统提示词（追加在模板之后）
  },
  "settings": { "rate": 1.5, "volume": 0.9, "autoNext": true,
                "lastCoursePath": "", "lastEpisodePath": "",
                "theme": "dark" }   // dark|light；渲染层另以 localStorage 缓存该值做首帧应用（防闪色），learn.json 为准
}
```

`userData/ai-history.json`（M7，独立文件，300ms 防抖落盘，图片 base64 不落盘）：

```jsonc
{ "messages": [ { "role": "user"|"assistant", "content": "文本", "ts": "ISO",
                  "imgAt": "04:38"   // 仅截图消息带此标记
                } ],
  "updatedAt": "..." }
```

- 上限 200 条，超出从最旧处**整对**丢弃；
- 回传 API 时只取最近 20 条纯文本（旧截图不重发，省 token）；本次截图消息带 `image_url`。

> 路径全部用**绝对路径**做键；课程 key：扫描课程=目录路径，导入课程=`custom:<id>`。

## 二、一阶段交接（当前状态）

### 2.1 验收记录（2026-09-18 实测）

用一个 99 集、按中国大学MOOC 命名（`[1.2.N]--标题.mp4`）的课程目录实测通过：
- 扫描：科目=数学，课程=高数(99集)/概率论(0集)/线代(0集)；空课程正常显示；
- 排序：1→99 数值序正确（资源管理器字母序会把 [1.2.10] 排到 [1.2.2] 前，本应用已解决）；显示名正确去掉 `[1.2.N]--` 前缀；
- 播放：file:// 直链真实播放、空格键起播、时间轴走动；
- 持久化：每 3 秒节流写盘，重启后自动恢复上次课程/分集/进度位置；
- 首启空状态、设置弹窗、日志零报错。

### 2.2 关键实现规则（改动前必读）

1. **扫描规则**（main.js `scanRoot`）：
   - 根的一级子文件夹里**直接有视频** → 根=科目，一级文件夹=课程；
   - 否则一级子文件夹**递归(深度≤2)含视频**的作为科目（兼容把课程目录的上一级当根目录：无视频的杂物文件夹自动排除），其子文件夹=课程；
   - 课程内递归(深度≤2)收集视频+文档，隐藏/系统目录跳过。
2. **排序**：有 `[x.y.z]` 括号编号 → 各段数值比较；无编号 → `Intl.Collator('zh-Hans-CN', {numeric:true})`；混合时括号编号优先。
3. **讲义匹配**：文档名中的数字恰好命中**唯一**分集的末位编号 → 挂到该集；否则为课程级资料。
4. **进度持久化时机**：timeupdate 每 3s / 暂停 / 换集 / 页面隐藏；>90% 判定看完。

### 2.3 踩坑记录（新会话/新人必看，勿重蹈）

| 坑 | 结论 |
|---|---|
| CSP 禁内联样式 | 页面 CSP 为 `style-src 'self'`，`style="..."` 属性、`setAttribute('style', …)`、`<style>`/`innerHTML` 注入样式**都会被拦**（曾致弹窗叠加）。**但 CSSOM 直接赋值不受 CSP 限制**——`el.style.width='300px'`、`style.setProperty('--x',…)` 实测可用（v0.4.3 分隔条/悬停预览定位即依赖此，推翻早前"JS 改 .style.* 全拦"的误记）。显隐一律用 `.hidden` 类不变 |
| preload 沙箱 | 默认 sandbox:true，preload 里**只能** `require('electron')`，Node 模块（如 `url`）不可用；file:// 地址由 preload 手写 `fileUrl()` 分段编码生成 |
| 自定义协议方案已弃用 | `protocol.handle('media')` 在 Chromium URL 规范化（host 小写化/补尾斜杠）下路径被改写，视频 404；已改用 file:// 直链，相关代码已删除，**不要走回头路** |
| userData 目录名 | 跟随 `package.json` 的 `productName`（学习播放器）→ `%APPDATA%\学习播放器\learn.json`。**打包/改版时 productName 不能变**，否则用户进度"丢失" |
| Electron 二进制下载 | 必须走 npmmirror（.npmrc 已配）；手动跑 install.js 时也要显式带 `ELECTRON_MIRROR` 环境变量 |
| 验证手段 | 视觉模型看截图可能**臆测**播放画面（曾把黑屏描述成"正在播放 1:02:33"）。播放是否真实生效以 `learn.json` 的 position 增长和 `ELECTRON_ENABLE_LOGGING=1` 控制日志为准 |
| 手改 learn.json | 中文路径 + 反斜杠转义，别用 shell printf 拼，用 Node 读写；**bash 双引号里 `'E:\\v'` 会被吃成 `\v`（垂直制表符）**，一律写临时 .js 脚本执行（曾写坏 roots，用 `E:'\\'+'vdsplayer'` 拼接规避） |
| 单实例锁 | 二次 `npm start` 会静默退出（`requestSingleInstanceLock`）并把旧实例拉到前台——验证新代码前先 `taskkill` 旧 electron 主进程，否则你以为在测新代码其实在测旧的 |
| 最小化窗口截图全黑 | 窗口最小化（bounds=-32000）时截屏内容为纯黑，视觉模型会误报"界面没渲染"。先 `open_application` activate 恢复再截图 |
| UIA 自动化（Windows） | Chromium 的 UIA 树**倒序**列出兄弟节点且文本配对不可靠，曾把正确的"第1集"读成"课程资料"；无 aria-label 的按钮显示为匿名 pressable（甚至和整行混在一起）。结论：① 读界面文字用**截图+视觉**复核，别只信 UIA 文本配对；② 要语义点击的按钮**必须加 aria-label**（讲义 ✕/🔗 已加）；③ 像素坐标点击有 10-20px 系统性偏移，小按钮优先走 aria-label + `perform_action` |
| shell 复合命令短路 | `cd xxx && node --check A && taskkill …`：第一步失败后 **kill 根本不会执行**，旧实例继续占单实例锁，后续 npm start 秒退还以为在测新代码。杀进程单独执行，勿挂在 `&&` 链尾 |
| 管道吃退出码 | `npm run dist \| tail -40` 使整条命令退出码=tail 的（0），**构建失败显示"成功"**。用 `> /tmp/build.log 2>&1; echo $?` 重定向方案 |
| ICO 格式（electron-builder） | resedit **不认 PNG-in-ICO**（Offset out of bounds）；自写 ICO 时 **ICONDIRENTRY 字段偏移**为 条目起始6+4/6/8/12 → planes@10 bpp@12 size@14 offset@18（写错+2 即崩）。`scripts/gen-icon.js` 为标准 BMP 条目 ICO，可直接复用 |
| NSIS 向导式安装包 | `oneClick:false` 时 `/S` 静默安装**无效**（进程秒退、什么都没装）；且目录页"安装"按钮初始禁用，需向路径框 set_value 确认目标后才激活；完成页会自启应用（自动化验收时注意单实例锁） |
| tasklist 中文进程名乱码 | `tasklist \| grep 播放器` **匹配不中**（tasklist 输出 GBK，Git Bash 管道按 UTF-8 匹配）——曾因此漏掉正在运行的便携版。查进程用 PowerShell `Get-Process` 按 `Path -like '*vdsplayer*'` 匹配（M7 实测教训） |
| 打包版与 dev 版互斥 | dist 便携版/安装版与 `npm start` 共用同一 userData（productName 相同）→ **单实例锁互斥**：打包版开着时 dev 版静默退出（零输出）。验收 dev 代码前先确认没有打包版在跑 |

**v0.4.1 修复（2026-09-23）：空格/方向键失灵（焦点滞留）**

- 现象：点过 AI 按钮/首页等顶栏按钮、或用过搜索框/AI 输入框、或拖过进度条后，空格不再暂停、左右方向键不再快进快退；
- 根因：Chromium 点击**非可聚焦元素**（视频/分集行/div）不移走焦点 → 焦点滞留在 button（空格再次触发按钮）、INPUT/TEXTAREA（空格进输入框、方向键移光标）、input[type=range]（方向键微调滑块）、select（方向键改选项）上，keydown 处理器按 INPUT/SELECT/TEXTAREA 守卫提前 return。CDP 实测：AI 输入框聚焦后**点视频焦点也不走**；
- 修复（renderer.js）：① 全局 click 委托——点过 button 即 blur；点过 range 即 blur；点击输入框以外任意区域时 blur 已聚焦的 INPUT/TEXTAREA；② change 委托——select/range 变更后 blur；③ AI 面板关闭路径显式 blur 输入框；
- 回归实测（CDP 真实按键注入）：AI 面板开+输入框聚焦 → 点视频 → 空格暂停 ✓；方向键 ±5s ✓；拖进度条后方向键仍快退（非滑块微调）✓；点 AI 按钮后空格不再误开面板 ✓。AI 输入框**聚焦期间**空格/方向键归输入框（打字场景，属预期），点别处即恢复；
- 前端脚本缓存版本号递增至 `?v=2`（防 Code Cache 旧字节码，见坑表）。

**v0.4.2 修复（2026-09-23）：AI 回复中 `\(..\)` / `\[..\]` 公式不渲染**

## 四、三阶段方案：格式兼容与分发（✅ 已全部交付，见 2.7 验收记录）

### 4.1 MKV/FLV/TS 无损转封装播放

**目标**：容器不支持但编码兼容（H.264/AAC）的视频，应用内直接播，无感知延迟最好、可接受短暂等待。

**交互**：
- 点击非 playable 分集 → 底部浮条：「正在转封装… ██████ 43%」（首次）→ 完成后自动起播；已有缓存的分集行加小图标，点击直接播；
- 编码不兼容（HEVC/老编码）→ 维持现状（系统播放器兜底）。

**实现**：
1. 新 IPC `remux-start {path}` / `remux-status`：
   - `ffprobe -show_entries stream=codec_name` → video∈{h264} 且 audio∈{aac,mp3} 才走 `-c copy`，否则返回 `unsupported`；
   - `ffmpeg -i <src> -c copy -movflags +faststart <userData>/remux/<md5(path|size)>.mp4 -progress pipe:1`，解析 `out_time_ms/total_size` 报进度；
   - 幂等：缓存存在直接返回 `ready`；转封装失败的文件加坏标记不再重试；
2. 渲染层 playEpisode：playable=false 时先查 remux 结果，`ready` → 播 remux 文件；
3. 缓存治理：设置页显示 remux/thumbnails 占用，「一键清理」。

**风险与对策**：RMVB/AVI 等 `-c copy` 不兼容 mp4 容器 → ffprobe 判定直接归入"系统播放器"；E 盘若为机械盘，首次转封装 IO 慢 → 进度条明示，不阻塞其他操作（独立进程）。

**验收**：任选一个 H.264 的 MKV，点击 → 10 秒级完成转封装并内播，进度条拖动正常；重启后秒开（缓存命中）。

### 4.2 打包分发（electron-builder）

- 依赖：`electron-builder`（dev）；产物双目标：**NSIS 安装版** + **便携版 exe**（portable）；
- 配置要点：
  - `appId: com.vdsplayer.app`，`productName: 学习播放器`（⚠ 必须与现值一致，保证 userData 沿用、老用户进度无缝）；
  - `files: ["main.js","preload.js","renderer/**","package.json"]`，asar 打包；
  - 图标 256×256 `.ico`（首版可用程序生成的简洁图形，后续可换）；
  - ffmpeg **不内置**：体积与许可考虑，检测 PATH，缺失时缩略图/转封装功能置灰并在设置页提示安装路径，其余功能不受影响；
- 产物预估 ~85MB；升级 = 覆盖安装，数据在 `%APPDATA%` 不受影响。

**验收**：双击安装版 exe → 安装 → 开始菜单出现「学习播放器」→ 打开即见旧进度；卸载时询问是否保留数据。

## 六、四阶段方案：AI 提问侧边栏（✅ 已交付 v0.4.0，见 2.8 验收记录）

> 状态：**已实施**。方案四项关键决策 —— **Markdown+KaTeX 数学公式渲染 / 单会话滚动 / 仅 OpenAI 兼容协议 / 截图提问** 均按定稿落地。实施中与方案的差异：① marked v18 无 dist min 版，自托管 `lib/marked.umd.js`；② CSP 的 img-src 增加 `data:`（截图预览）；③ `build.files` 需显式加 `ai-bridge.js`（方案 6.7 判断疏漏）；④ 全屏隐藏侧栏用 CSS `:has()` + fullscreenchange 兜底双保险；⑤ 快捷 chips 点击填入输入框而非直接发送（按 6.6 原设计）。

### 6.1 功能概述

播放器右侧新增 AI 问答侧边栏：

- **流式对话**：打字机式输出，可中断；
- **Markdown + 数学公式渲染**：粗体/列表/代码块 + `$...$`、`$$...$$` LaTeX（数学学习场景刚需）；
- **截图提问（多模态）**：一键抓取当前视频帧（精确到播放秒）+ 问题发给视觉模型，问「屏幕上这题怎么做」；
- **上下文感知**：自动把当前科目/课程/分集/播放位置注入 system 提示，AI 知道你在学什么；
- **自定义 API**：用户自配 OpenAI 兼容端点（OpenAI / DeepSeek / Kimi / 智谱 / Ollama 本地 / 各类中转站），设置页带服务商预设下拉与「测试连接」；
- **历史持久化**：单会话滚动（上限 200 条），重启保留、一键清空；
- Ctrl+I 快捷开关；白天/夜间主题与全屏行为适配（全屏时隐藏侧栏）。

### 6.2 核心架构决策（为什么这样做）

| 决策 | 理由 |
|---|---|
| **网络请求全部走主进程**（Electron `net` 模块），渲染层零 fetch | ① CSP `default-src 'self'` 无 connect-src，渲染层 fetch 外部 API 会被拦，不放宽 CSP（避免扩大 XSS 面）；② API Key 不进渲染层网络栈；③ net 走 Chromium 网络栈，自动感知系统代理。流式响应由主进程解析 SSE，按 requestId 经 `webContents.send` 推送 |
| **截图用主进程 ffmpeg 抽帧，不用 canvas** | file:// 页面 drawImage file:// 视频 → canvas 被 taint → toDataURL 抛 SecurityError；ffmpeg 方案复用现有 findFfTools/runTool 管线，可拿原始分辨率、`-ss` 精确到当前播放秒，对 MKV 等自动改用 remux 缓存 mp4 |
| **前端依赖自托管** renderer/vendor/：marked.min.js + dompurify.min.js + KaTeX(js+css+fonts ≈1MB) | CSP `script-src 'self'` 允许本地文件；无 CDN、无构建步骤、离线可用。KaTeX 字体走 `font-src`（回落 default-src 'self'）本地文件 ✓ |
| **历史独立文件 ai-history.json，主进程代读写** | 防止 learn.json（每 300ms 整体落盘）被对话膨胀；渲染层全权持有会话状态，主进程只做文件代理，ai-bridge 无状态 |
| **流式期间显示纯文本+光标，done 后一次性渲染 Markdown/公式** | 避免流式中途公式反复重排闪烁；渲染开销一次性 |

```jsonc
  "model": "deepseek-chat",
  "contextEnabled": true,                      // 自动附带当前课程/分集上下文
```

```jsonc
  "updatedAt": "..." }
```

- 上限 200 条，超出从最旧处**整对**丢弃；
- 回传 API 时只取最近 20 条纯文本（旧截图不重发，省 token）。

### 6.4 IPC 通道（新增，沿用第二节通道表风格）

| 通道 | 方向 | 说明 |
|---|---|---|
| `ai-save-config` | R→M | ai 段整体覆盖 → true |
| `ai-test` | R→M | → {ok, message}：非流式发 max_tokens=8 的 ping，错误分类回报 |
| `ai-send` | R→M | {messages:[OpenAI 格式，含 vision 图片消息]} → {ok, requestId}；单在途，新请求自动 abort 旧请求 |
| `ai-abort` | R→M | 中断在途请求 |
| `ai-history-load` / `ai-history-save` / `ai-history-clear` | R→M | 历史文件代读写 |
| `ai-capture-frame` | R→M | {path, position} → {dataUrl}：`ffmpeg -ss <秒> -i <src> -frames:v 1 -vf scale=1280:-2 -q:v 5` JPEG base64（约 100-300KB/张） |
| `ai:chunk` / `ai:done` / `ai:error` | M→R | push 事件 {requestId, delta? / content? / message?} |

preload 新增：`aiSaveConfig / aiTest / aiSend / aiAbort / aiHistoryLoad / aiHistorySave / aiHistoryClear / aiCaptureFrame` + `onAiEvent(cb)`（返回退订函数）。

### 6.5 主进程：ai-bridge.js（新文件 ≈220 行）

main.js 仅加 3 行：`require('./ai-bridge')` + 在 registerIpc() 末尾调 `registerAiIpc(() => mainWindow)`。

- `sendChat(messages, handlers)`：`net.request(POST baseUrl + '/chat/completions')`，头 `Authorization: Bearer <key>`，体 `{model, messages, stream:true}`；
